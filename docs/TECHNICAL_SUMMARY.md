# Sahil Atlas - Asset Resilience Score

Challenge 01 | ADCMC and Khalifa University | 17 November 2026 | Model gen0-1.1.0

**Purpose and approach.** Sahil Atlas prioritizes fictional critical facilities using the supplied deterministic 0-100 resilience-risk formula. An adapter validates fixed JSON schemas and supplies facility, warning, exposure, measure, plan and optional sub-asset records. The engine computes threat, vulnerability, recovery gap and consequence at full precision, publishes a whole-number score, applies category overrides and reports evidence confidence separately. It evaluates the strongest live risk on each exposed channel and reports six normalized vulnerability-weight sensitivity scenarios.

**Updates and explanation.** Warning imports rescore exposed facilities while preserving unaffected records. Dated input imports retain facility, exposure and population versions and atomically store the update with a full portfolio scoring run. Changes compare against the previous-day cutoff using individual-input counterfactuals; named audit/control rows match by identity. Zero-effect metadata changes remain auditable. Weakness drivers and costed levers use the same scoring engine. SQLite preserves score history and events. Every score records a time, model version and input hash. Live mode performs a daily full run; replay restores inputs effective at each historical date.

**Analyst workflow and portability.** The landing page leads to the existing dashboard, with a ranked, filterable register, facility cards, drivers, plans and 7/30/90-day trends. An offline coordinate map and ten illustrative 3D asset types support exploration. Combined measures are hypothetical; a check-up flag waits for human review. Downloadable HTML reports preserve vector graphs, source details, scenarios, costs and JSON evidence. Browser printing produces PDF reports. The app runs with Python 3.10+ using one command, with no third-party application packages, cloud services or runtime downloads. The second sample loads through the same adapter.

**Validation.** All 45 Python tests and 18 JavaScript tests pass. The plant reproduces 51.9 to 70.9, published 52 to 71, confidence B, driver effects 19.0/10.3/4.7 and the combined 50.2 scenario. All 120 supplied before/after score, band and confidence results match. The 500-facility warning test completed in 0.422 seconds in this environment. An end-to-end API check exercised 22 local requests with outbound connections denied, including warnings, scenarios, reports, input updates and the 12-facility second sample. Test code and regeneration scripts accompany the submission.

**Assumptions and limits.** The baseline represents static supplied facts; only explicitly recorded updates reconstruct later changes. The schema lacks an exercise date, so full exercises are assumed current. Confidence follows the supplied reference conventions. Some two-decimal pillar displays differ by 0.01 at rounding boundaries. Geometry is illustrative, not surveyed; risk scores are not disruption probabilities. Arabic/RTL and the optional predictive ML challenger are not implemented. Chromium could not launch in the build environment, so full browser, WebGL, PDF pagination and the presentation-laptop offline rehearsal remain outstanding. The organizer's hidden dataset is unavailable and untested.

**AI use and ownership.** AI assistance supported brief review, implementation, tests, documentation and validation analysis. Deterministic code calculates every score and scenario from supplied synthetic data; no numerical results come from generated prose. The submission remains subject to ADCMC ownership and private-sharing requirements. The applicant should review and understand the implementation before presenting it.
